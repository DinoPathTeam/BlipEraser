# BlipEraser

An app uninstaller and system cleaner for **Arch Linux** and Arch-based distributions.

BlipEraser fills the gap left by graphical package managers: apps installed
**manually** (AppImages, loose folders from third-party launchers, unpackaged
programs) that **no package manager tracks**, so the usual "uninstall" tools
cannot see them.

## Features

- **Overview**: system health gauge (*GOOD / FAIR / POOR*), live CPU/GPU/RAM/disk stats and a "Clean now" summary of the recommended cleanup.
- **Uninstaller**: one list for `pacman` packages and manual folders, with sorting, search and **manual per-row selection** (there is deliberately no "select all", to prevent accidental mass uninstalls). Packages are removed with `pkexec pacman -Rns`.
- **Cleaner**: *recommended cleanup* (`~/.cache`, the pacman cache `/var/cache/pacman/pkg` and logs in `/var/log`) and *manually installed apps* (loose folders and AppImages in the scan paths).
- **Safety confirmation**: every destructive operation lists exactly what will be removed; selections over **5 GiB** show a highlighted warning. Confirmation is mandatory, there is no "don't ask again".
- **Performance tweaks**: all optional, **off by default**, each with a detailed explanation (mechanism, consequences, benefit) in the app:
  - **TRIM** (`fstrim.timer`) for SSD/NVMe.
  - **zram** (compressed swap in RAM) via `zram-generator`.
  - **zswap** (kernel compression cache in front of disk swap).
  - **Fastest mirrors** via `reflector`.

  The tweaks never override what your distribution already manages: if the system already provides zram (e.g. CachyOS), uses a mirror list generated by another tool, or has zram as swap (which makes zswap redundant), the tweak is shown **disabled with the reason**. If the system later loses a setting you enabled, the app tells you and offers to re-apply it instead of silently overwriting your choice.
- **Settings**: theme, fonts, language (ES/EN, switched live) and activity-log management.

## Supported systems

| Status | Distributions |
|---|---|
| **Tested** | CachyOS |
| **Expected to work, untested** | Arch Linux, EndeavourOS, Garuda Linux, Manjaro |

BlipEraser needs `pacman`, `systemd`, polkit and D-Bus on the system bus. Other
Arch derivatives that provide those may work; if you try one, an issue
reporting the result (good or bad) is very welcome.

## Requirements

- An Arch-based distro with `pacman`, `systemd`, polkit (`pkexec`) and D-Bus.
- Python 3.11+, **PyQt6** and **PyGObject** installed with `pacman` (not pip).
- Optional: `gst-libav` (H.264 splash video; the app falls back to a logo animation without it) and AppArmor (the daemon confinement profile is included in `packaging/apparmor/`).

## Installation

### Build the package locally (PKGBUILD)

`packaging/aur/` contains the `PKGBUILD` that builds the release tarball and
installs everything (app, privileged daemon, polkit policy and rules, D-Bus,
systemd unit, AppArmor profile, desktop entry):

```bash
git clone https://github.com/DinoPathTeam/BlipEraser.git
cd BlipEraser/packaging/aur
makepkg -si
sudo systemctl enable --now blip-eraser-privileged.service
```

> The daemon runs as root and is recommended but optional: without it the app
> falls back to `pkexec` for cleaning. Only members of the `wheel` group can
> authorize its actions.

### From source

```bash
# 1. System dependencies (PyQt6 and PyGObject must NOT come from pip)
sudo pacman -S python-pyqt6 python-gobject polkit gst-libav

# 2. Get the code
git clone https://github.com/DinoPathTeam/BlipEraser.git
cd BlipEraser

# 3. Deploy the privileged daemon (idempotent; asks for sudo; re-run after code changes)
./scripts/install-daemon.sh

# 4. Run without installing...
PYTHONPATH=src python -m blip_eraser
```

To get the `blip-eraser` command, use a virtualenv that reuses the system packages:

```bash
python -m venv --system-site-packages .venv
source .venv/bin/activate        # fish: source .venv/bin/activate.fish
pip install -e .
blip-eraser
```

### Tray icon (optional)

`blip-eraser-tray` runs a separate, lightweight tray icon (it does not open the main window). Nothing is computed while it idles: opening its menu shows CPU/RAM/disk and the recoverable space, calculated on demand. "Quick cleanup…" opens BlipEraser straight into the usual cleanup confirmation; the tray itself never deletes anything. Once at start it uses the same 24-hour update cache to notify about a new version, and warns (at most once a day) when 5 GiB or more can be recovered. The menu has toggles to start with your session and to silence notifications (`"tray_notifications": false` in `prefs.json`). Native install only: the Flatpak does not ship it.

### Flatpak

Each [release](https://github.com/DinoPathTeam/BlipEraser/releases/latest) includes a `.flatpak` bundle. Install the host daemon first (`./scripts/install-daemon.sh`), then `flatpak install --user BlipEraser-v<version>-x86_64.flatpak`.

> **The Flatpak is not a sandbox here.** To manage the host it needs
> `--filesystem=host` and `--talk-name=org.freedesktop.Flatpak`
> (`flatpak-spawn --host`), which gives it effectively full access to your
> session. Prefer the native install if you care about confinement.

Step-by-step guides for beginners: [`Installation guide.en.txt`](Installation%20guide.en.txt) · [`Installation guide.es.txt`](Installation%20guide.es.txt).

## Architecture

```
main.py ── PyQt6 check → first-run language → splash + startup checks
            │
            ▼
MainWindow (header + sidebar + pages + status bar + log panel)
  pages/   overview · uninstaller · cleaner · performance · settings · ...
  widgets/ splash, tables, dialogs, background-scan mixin
            │
            ▼
utils/  pure modules, no Qt (testable without a display)
  scan / apps / pacman (detection) · validation / privileges / dbus_client
  (security) · performance (tweaks) · i18n / theme / config / log ...
      │                                      │
      ▼                                      ▼
D-Bus system bus → root daemon         pkexec + polkit
  Ping, CleanSystemPaths                 pacman -Rns (uninstall)
  (cleans only cache and logs)           tweaks: systemctl, config files
```

Stack: Python ≥ 3.11 · PyQt6 + QSS · D-Bus via PyGObject (`gi`) · polkit · systemd · AppArmor · Bash installers.

## Security model

- **Confirmation first**: every destructive operation lists what will be removed and needs explicit confirmation. Selections over 5 GiB get an extra warning.
- **Privileges per action**: root actions are authorized through polkit on every request (the polkit rules accept only `wheel` members, and polkit may cache the authorization briefly). There is no persistent "sudo mode".
- **Package removal does not go through the daemon.** It is a `pkexec pacman -Rns` call, authorized by a polkit prompt, so the daemon never needs write access to the package database or pacman hooks.
- **The privileged daemon is deliberately small.** It exposes only `Ping` and `CleanSystemPaths` on the system bus, and only deletes inside an allowlist: `/var/cache/pacman/pkg` and `/var/log` (never `/var/log/journal` nor BlipEraser's own logs). Paths are normalized before the check, and deletion walks the tree by file descriptor with `O_NOFOLLOW`, so symlinks are never followed.
- **Abuse limits**: at most 10 destructive calls per minute per caller, one in-flight operation per user, and the rate limit also counts denied or cancelled authorizations.
- **Hardening**: the systemd unit uses `NoNewPrivileges`, `ProtectSystem=strict`, `ProtectHome`, `PrivateTmp`, `MemoryDenyWriteExecute` and a system-call filter, and is confined by an AppArmor profile when AppArmor is active.
- **Network use**: the only network request is an update check against the public GitHub Releases API, made in the background at most once every 24 hours; it sends nothing about your system and only shows a small notice in the status bar (no automatic download). Set `"check_updates": false` in `~/.config/blip-eraser/prefs.json` to turn it off. The Flatpak build has no network permission, so it never checks.
- **Audit trail**: security-relevant events are written to `~/.cache/blip-eraser/diagnostics.log`.
- **No silent changes**: the app installs a package (`zram-generator`, `reflector`) only when you enable a tweak that needs it, and it never touches the bootloader.
- **Limits you should know**: this is a young project and has not had an independent security audit. The Flatpak build has no real sandbox (see above).

## Dependency checking

On startup the app checks its dependencies on two levels. Without PyQt6 no window can be drawn, so it prints the install command and exits. With the GUI up, it checks in the background that `pacman` and `pkexec` exist and, if one is missing, shows what it is and the exact command to install it. **BlipEraser never installs dependencies by itself.**

## Development and tests

The logic (scanning, validation, pacman commands, tweaks) lives in `src/blip_eraser/utils/` without any PyQt6 dependency, so it can be tested headless:

```bash
pytest tests/ -q
```

GUI tests need PyQt6 and are skipped when it is missing; run them headless with `QT_QPA_PLATFORM=offscreen pytest tests/ -q`. CI runs `compileall` and the test suite on every push and pull request to `main`.
